## スマホで遊ぶ

**手軽に遊ぶだけなら**、公開URLをスマホのブラウザで開けばそのまま遊べる。

**単体アプリとして入れたい場合は、自分のURLに置く必要がある。**
Claude のアーティファクトとして配信されている画面は claude.ai のページの中の iframe で動いているため、
そこで「ホーム画面に追加」しても登録されるのは外側の Claude のページであって、このゲームではない。
埋め込まれた側からは、OS が見るマニフェストやアイコンに手を出せない。

### 配布用一式を作って置く

```
node build.js          # docs/ が出来る
```

`docs/` の中身をまるごと HTTPS のURLに置く。サブフォルダでもよい（全て相対パス）。
置いたらスマホのブラウザで開き、「ホーム画面に追加」。

| ファイル | 役割 |
|---|---|
| `index.html` | `<html>/<head>/<body>` を備えた正式な文書に組み直したもの |
| `manifest.webmanifest` | アプリ名・全画面起動・アイコン・配色 |
| `sw.js` | 圏外でも遊べるようにする Service Worker |
| `icon-*.png` | ホーム画面用（180 / 192 / 512 とマスク用 512） |
| `README.txt` | 置き場所と更新手順 |

置いたあとに出来ること:

- アドレスバーの無い**全画面アプリ**として起動する
- 一度開けば**圏外でも遊べる**
- 新しい版を上書きすると、次に開いたとき更新の案内が出る

`index.html` は「アーティファクト形式」で `<html>` を持たない。`build.js` は `</style>` の位置で
頭と胴に割り、正式な文書に組み直したうえで、埋め込みでは効かない宣言（マニフェスト・アイコン）を
`head` に足す。中身は本体と1バイトも変えない（検証項目「ルールエンジンが本体と同一」）。

### 背景

タイトルと対局中の背景は canvas で描いている。水中光学らしく見せるための要素は次のとおり。

- 地の色（水面寄りの藍緑から深部の黒へ）＋ 粒状（平坦なグラデーションに出る縞を潰す）
- 頭上の水面のほのかな明るさ
- 差し込む光条5本（両縁を溶かした帯を、ゆっくり揺らして明滅させる）
- **光の斑** ── 水面の起伏が集めた光。輪郭を崩した柔らかい塊を30個、大きさ・向き・明滅を変えて散らす
- 泡 ── 遠景・中景・近景・手前（焦点外）の4種を焼き分ける。中は素通しで膜だけが光る。
  上から差した光は泡を透けて**下の縁に集まって明るい弧**を作り、上の縁には水面の照り返しが細く乗る。
  膜の内側にもう一本暗い縁が出て輪郭が二重に見え、鏡面反射は光源側（左上）に鋭い芯を持つ。
  薄膜なのでわずかに色づく。**大きい泡ほど直径に対する膜は細い** ── ここが作り物との分かれ目。
  上りながら周期の違う2つの揺れでジグザグに進み、大きいものは形が縦横に脈打つ。
- 微粒子（マリンスノー）
- 周辺減光（監視塔の中にいる圧迫感）

**繰り返し模様は使っていない。** 最初はコースティクスを継ぎ目なく敷けるタイルとして焼いたが、
どう調整しても「迷路模様のテクスチャ」に見えたため、反復をやめて斑を散らす方式に変えた。

描画費用は工程ごとに実測して詰めた（詳細は下の「検証で見つかって直したもの」）。
現在は **1フレーム 5.0ms**（ソフトウェア描画・504x804 で 60fps 予算の30%）。

### 手触り

- **効果音** ── Web Audio で合成しており、音源ファイルを持たない（容量は増えない）。
  札の選択、賭け、エアを失う音、秒読み、天災の衝撃、決着。
  全体を水中らしく濁らせ、**酸素が減るほど濁りが深くなる**（意識が遠のく感じを音で出す）。
  最初の操作で鳴り始める（自動再生の制限のため）。
- **触覚** ── Android では振動を併用。札の選択は極短く、天災は強く。
- **押し込みの手応え** ── 全ての操作に反応を返す。押せない場所を押したときも音で分かる。
- 音と振動は個別に切り替えられ、設定は端末に保存される。
- **決着の段取り** ── 役名 → 判定 → 天災 → エアの移動、の順に運ぶ。
  場のエアはチップとして勝者へ飛び、着いてから手持ちの数字が動く。画面に触れれば飛ばせる。

### スマホ向けに入れてあるもの

- 画面の寸法が変わっても背景を撒き直さない（下の「検証で見つかって直したもの」参照）
- ノッチとホームバーを避ける（`env(safe-area-inset-*)`。ゲージが隠れない）
- 長押しの文字選択とダブルタップ拡大を止める（ルール画面だけは選択・コピー可）
- 引っ張って更新（pull-to-refresh）とゴムバウンドを止める
- 対局中は画面を消さない（Screen Wake Lock。非対応端末では黙って諦める）
- レイズのつまみを掴みやすい大きさに

## 更新

タイトル画面の下に版番号と「更新を確認」がある。新しい版が出ていれば帯が出て、
「今すぐ更新」で切り替わる。起動時と、アプリに戻ってきたときにも自動で確認する。

経路は2つあり、環境に応じて使い分ける。

- **配布版（自分のURL）** … Service Worker が新しい `sw.js` を検知する。
  「今すぐ更新」で待機中の worker を有効化して読み込み直す。**これが本命。**
- **それ以外** … 自分自身のURLを取り直して `app-version` を読み比べる。
  取得できない環境では「自動確認ができませんでした」と出し、手動の再読み込みを案内する。

どちらの経路でも最新版になる（URLは常に最新を返すため）。

## 遊び方

原作では1階（貘・ラロ）がベット、2階（ハル・梟）が役作りを担当するが、
本作ではプレイヤーが**両方**を操作する。

1. **数字を選ぶ** — 手元の5枚の金属板から1枚を、**30秒以内**に場にオープンする。毎回戦1枚ずつ、5回戦で使い切る。時間が来れば1枚が勝手に押し出される。
2. **役作り** — 100秒。1セットのトランプから5枚選び、**合計をオープンした数字に一致**させる。
3. **ベット** — 30秒。レイズできるのは場のエア総数の半分まで。時間が来たらレイズ不可。
4. **決着** — 強い役の側が場のエアを総取り。札が1枚でも重複していたら**天災**。

**役作りはベットより前に来る。** こうしないと、降りることで札を温存できてしまうため。
出した5枚は、降りても・負けても・合計を間違えても、二度と使えない。
そのぶんベットの局面では**自分の手が確定していて、相手の手だけが分からない**という、
本来のポーカーに近い読み合いになる（相手の数字から何が組めるかは分かる）。

双方がミスしたときのやり直しは、**ベットのあとに交互で**行う。

### 呼吸 ── 迷う者ほど早く沈む

エアは賭け札であり、同時に酸素ボンベでもある。**エア1枚 ＝ 100秒**ぶんの酸素。
盤面に着いている間は常に減り続け、尽きると自動的にエアを1枚消費して補充する。
手持ちが0のまま回戦を終えると溺死して負け。

**自分の選択が済むまでは、その減りが2倍になる。**
数字を選ぶ間、自分のベット手番、役を提示するまで ── 迷えば迷うほど息を失う。
決めてしまえば通常の速さに戻る。ゲージの `O2` が `O2×2` に変わるのが目印。

降りて浮くのは賭けたエアだけ。役作りは先に済ませているので、その酸素は戻らない。

CPU は待ち時間を短くしてある代わりに、**思考秒数をそのまま酸素に計上**する。
梟が数字や役を決めた直後に梟の酸素が落ちるのはそのため。難易度が高いほど短い時間で解くので上級ほど酸素も残るが、
人間側が速く解けばその差はひっくり返せる。

同じ打ち方でも、役作りに **25秒しかかけない側は75秒かける側に勝率63.5%**（検証項目13）。
15秒対90秒なら70.6%まで開く。速さはそのままエアになる。

### トランプは1組を二人で使う

原作どおり、**ジョーカーを除く1組のトランプを両者で共有する**。どちらが使った札も山から消え、二度と戻らない。
1回戦でおよそ10枚（重なったぶんだけ少なく）失われ、最終回戦の山は12〜17枚しか残らない。

**同じ山から選ぶからこそ、札が重なる。** これが天災である。
山が痩せるほど選択肢は同じ数枚に収束し、終盤の天災はほとんど避けられない。
実測で天災は **1戦あたり 1.65 回**（別々の山だった頃は 1.33 回）、重なる札は平均 2.06 枚。

### 数字板 ── 帯を分けて配り、死んだ板は打ち直す

山を共有すると終盤の帯が急速に狭まる。実測すると、第5回戦で作れる合計は
**最も安全な 32 でさえ成立率 94.7%**で、固定の5枚配りで最終回戦を保証することは原理的にできない。
そこで2段構えにした。

1. **帯を分けて配る** ── 端に寄った数字（24未満・48超）は各自2枚まで。残り3枚は終盤まで組める中核帯（24〜48）から。
2. **死んだ板は打ち直す** ── 回戦の初めに、山が痩せてもう組めなくなった数字板は、
   その時点で組める数字へ打ち直される。

打ち直しは**救済であって得ではない**。必ず組める数字にはなるが、
元の数字が持っていた見込み（強い役を作れる可能性）は失われる。
端の数字を抱え込めば、ただの平凡な数字に化ける。実測では1戦あたり 1.07 枚が打ち直され、
そのほとんどは第4〜5回戦に集中する。

結果、**「組める役が無い」は 0.00%**（共有デッキにした直後は第5回戦で 25.6% だった）。

### ストレートフラッシュが出る合計数

連続する5枚の合計は必ず5の倍数になる。つまり
**15・20・25・30・35・40・45・50・55**、そして 10-J-Q-K-A の **47**。
この10個の数字だけがストレートフラッシュを組める。手元に来るかどうかは運であり、来なければ別の勝ち方を探すことになる。

ただし**ゲーム中にその印は一切出さない**。数字板にも場の数字にも注記は付かないので、
どの数字が何を組めるかは自分で見抜くしかない。（ルール画面には理屈だけ書いてある）

反対に端に寄った数字は組める役がごく限られる。**6** は A・A・A・A・2 の一通り、**64** は K・K・K・K・Q の一通りしかない。
強い役だが、その札が1枚でも欠ければ二度と組めない。しかも山は二人で削り合う。
**端の数字は、早いうちに切らなければ打ち直されて平凡な数字に化ける。**

### 細かい規定

| 項目 | 値 |
|---|---|
| 初期エア | 25枚 |
| トランプ | ジョーカーを除く**1組を二人で共有**。使った札は双方の山から消える |
| 数字板 | 各自「端に寄った数字2枚＋中核帯（24〜48）3枚」 |
| 打ち直し | 回戦の初めに、組めなくなった数字板は組める数字へ打ち直される |
| 数字板の選択 | 30秒（超過すると1枚が自動で押し出される） |
| 参加料 | 1回戦目1エア、以降1ずつ増加（計15） |
| ベットタイム | 30秒（超過後は15秒で強制決着） |
| 酸素の消費 | 常時1倍。自分の選択が済むまでは2倍 |
| 役作り | 100秒。双方ミスなら再度100秒（計3回まで、その後は場が次回戦へ持ち越し） |
| A の扱い | 合計では1、役の強さでは最強ランク（A-2-3-4-5 は5ハイの最弱ストレート） |
| 天災 | 負けた側が、奪われたエアと同数を追加で失う（残高が上限）。**そのエアは勝者に渡らず消滅する** |
| 進行 | 数字（30秒）→ 役作り（100秒）→ ベット（30秒）→ 決着 |
| 出した札 | 降りても負けても消費される。温存はできない |

### 暗算モード（原作準拠）

タイトル画面の「盤面」を切り替えると、2階の条件が原作どおりになる。

- 選んだ札の**合計数が表示されない**。自分で数えるほかない。
- 使い切った札に印がつかない。**どれを使ったかは記憶するしかない**。互いの使用済みも明かされない。
- 使用済みの札も選べてしまう。出した瞬間に**ミス**となり、その回戦を落とす。
- ヒント（思考 −25%）は役の種類だけを教える。中身は明かさない。
- CPU もこのモードでは記憶違い・計算違いを起こす（初級13% / 中級5% / 上級1.5%）。梟でさえ完全ではない。

### 対人戦

1台の端末を交代で使う。数字選びと役作りの前に目隠し画面が入り、
そこでは酸素が止まる（渡す時間で不利にならないため）。ベットは公開情報なので目隠しは挟まない。

## CPU

| 難易度 | 役作り | ベット | 数字板 |
|---|---|---|---|
| 初級 下っ端 | 上位4手からばらつく | 読みが粗く、賭けも雑 | ほぼ無作為 |
| 中級 立会人 | 最善手を約7割 | 相手の手を確率的に推定 | ある程度計画的 |
| 上級 梟 | 常に最善手 | 相手の理論上の最強手まで計算 | 温存と勝負を使い分ける |

思考にかかる秒数（＝酸素の消費）も難易度で変わる。役作りは初級52〜92秒、中級34〜72秒、上級21〜48秒。

上級は「自分の最善手が相手の理論上の最強手に確実に勝つ」ときに限り、
**勝ちを保ったまま重複しやすい札を選んで天災を狙う**。勝ち手を捨てることはない（検証項目11）。

CPUは相手の数字を知っている。山は共有なので「残っている札」は双方に等しく見えており、
プレイヤーも同じ情報を「相手の情報 / 山の残り」から見られる。CPU だけが得をする情報は無い。

## 検証

```
node tests/verify.js                        # ルールエンジン（依存なし）
npm i jsdom
node tests/ui-smoke.js                      # 画面の通し検証
node build.js && node tests/dist.js         # 配布用一式の検証
TARGET=docs/index.html node tests/ui-smoke.js   # 配布版も同じ検査に通す
```

`tests/verify.js` は `index.html` の `<script id="core">` をそのまま取り出して実行する。
ビルド手順はなく、`index.html` が唯一の実体。

主な検証項目:

- **探索器の正しさ** — 52枚の全組み合わせ **C(52,5)=2,598,960 通り**を総当たりし、
  各合計数の最強役が探索器の結果と完全一致することを確認。札が欠けた山でも同様に照合。
- **CPU 3,600戦の完走** — 実戦相当の思考時間を与えて全難易度を走らせ、
  毎tickでエア総量（常に50）・チップ非負・使用札数・提示手の合計などの不変条件を検査。
- **CPUの合法性** — 全ての指し手が規則の範囲内であること。エンジン側の救済処理
  （`cpuFallback`）が一度も発動しないこと。
- **難易度の単調性** — 上級 > 中級 > 初級 の勝率順が成立すること。
- **バランス** — 2種類の人間モデル（のんびり型／熟考型）との勝率を計測。
- **進行の順番** — 数字を開いたらまず役作り、双方が組み終えてからベットへ入ること。
  **降りても出した5枚は双方とも使用済みになる**こと（温存できない）。
  双方ミスのやり直しがベットのあと交互に行われること。
- **呼吸** — 選択中は10秒で20%（倍速）、選び終えると10%に戻ること、役作り100秒でエア2枚ぶん、
  数字板の30秒と自動押し出し、CPUの思考秒数が酸素に計上されること。
- **速さの価値** — 同条件なら席順で有利不利が出ないこと、
  役作りを25秒で決める側が75秒かける側に勝つこと（63.5%・呼吸2.97枚 対 7.62枚）、
  差が開くほど効き方も大きくなること（15秒対90秒で70.6%）。
- **共有デッキ** — 両者の山が同一であること、相手が使った札も自分の山から消えること、
  重なったぶんだけ山の減りが鈍ること。
- **数字板** — 各自「端2枚＋中核3枚」で配られること、中核帯の数字が全て出ること、
  S.F. 圏内の枚数が固定されないこと。
- **打ち直し** — 200戦を通して、回戦の初めに手持ちの数字板が全て組める状態であること
  （実測 0/検査した全枚数）。組めなくなった板が組める数字へ打ち直され、記録されること。
- **天災** — 追加没収が「奪われたエアと同数（残高が上限）」であること、
  失われたエアが**勝者に渡らず消滅**すること、勝者が受け取るのは場のエアだけであること。
- **スマホ対応と更新** — 版番号が埋め込まれ画面に出ること、全画面起動の宣言・アイコン・
  マニフェストが `head` に**重複なく1つずつ**入ること、`viewport-fit=cover` が効くこと。更新確認は
  「最新のとき」「新しい版があるとき」「通信が失敗したとき」「サーバがエラーのとき」
  「fetch が使えない環境」の5通りで、正しい案内が出て例外にならないことを確認。
- **配布用一式**（`node tests/dist.js`、44項目）— 正式な HTML 文書になっていること、
  マニフェスト・アイコン・Service Worker の宣言が head にあること、
  **版番号が本体・`sw.js`・マニフェストで一致し置換漏れが無いこと**、
  ルールエンジンと画面スクリプトが本体と1バイトも違わないこと、
  アイコンが宣言どおりの大きさの本物の PNG であること。
- **画面** — jsdom上で実際にボタンを押して7通り（標準4モード＋暗算3モード）を最後まで遊び、
  実行時エラーが出ないこと、画面の表示値が内部状態と常に一致すること、
  伏せた数字が漏れないことを確認。暗算モードでは合計・使用済みの印・相手の使用札が
  一切表示されないこと、誤った5枚が有効な役として受理されないことも検査。

### 検証で見つかって直したもの

- 検証用シミュレータがCPU2体の役作りを**直列**に消化しており、100秒を共有する仕様のため
  後手が必ずミスになっていた（勝率が先手917/後手239に偏った）。同時進行を再現する
  事象駆動シミュレータに置き換え、席順の偏りを検査項目に追加。
- CPU同士だと一瞬で指すため、**呼吸・溺死の経路が一度も走っていなかった**。
  思考時間を消費させるようにして、初めてその経路を検査下に入れた。
- ベットタイム切れでレイズ不可になっても、ボタンの表示が更新されず押せてしまった。
- 双方ミスで再挑戦になったとき、前回のミス理由が残って表示が古くなっていた。
- タイトル画面に更新の帯と版番号を足したところ内容が画面より高くなり、
  中央寄せ（`justify-content:center`）のせいで**上端がスクロールで到達できなくなっていた**。
  auto マージンに変え、収まるときだけ中央・あふれたら先頭からになるようにした。
- `build.js` の版番号差し替えが**先頭1件だけ**だったため、コメント中の `__VERSION__` に吸われ、
  Service Worker のキャッシュ名が `air-poker-__VERSION__` のまま出荷されかけた。
  ローカル配信して実ブラウザで動かしたときに発覚。全件置換に直し、
  置換漏れを検出する検査を `tests/dist.js` に追加した。
- **スマホでスクロールすると背景が壊れていた。** 画面の高さが変わるたびに背景を全部作り直し、
  泡と光の斑を撒き直していた。スマホはスクロールのたびにブラウザのツールバーが出入りして
  高さが変わるため、スクロール中ずっと泡が瞬間移動していた。
  実測すると、スクロール相当の resize 30回に対して**作り直し31回**。
  連続する resize は最後の1回だけ処理し、幅が同じで高さの変化が小さいうちは中身を触らず、
  作り直すときも既にいる泡は比率で置き直すようにして、**同じ操作で作り直し1回**になった。
  再発を防ぐ検査項目も追加。
- 手触りの結線を差し込む際、目印にした見出しの文言が CSS 側にも同じものが存在し、
  **JS がスタイルシートの中に入り込んで CSS 全体が壊れていた**。取り出して入れ直した。
- 背景を作り直した直後は **1フレーム 21.6ms**（60fps 予算の129%）とスマホでは到底動かない重さだった。
  工程を1つずつ外して実測したところ、**全画面のブレンド処理**が支配的で、泡や微粒子はほぼ無償と判明。
  対策は3つ ──（1）変化しない「地の色＋粒状」を焼き込んで毎フレームは複写だけにする、
  （2）周辺減光を canvas から CSS へ逃がす、（3）背景キャンバスを等倍で描く（費用は画素数に比例）。
  さらに斑の回転をあらかじめ焼き、光レイヤは光が届く上部76%だけを合成するようにした。
  結果 **2.9ms**（7.4倍）。
- 泡の膜を角度ごとに分割して描いていたため、重なりが**継ぎ目**として露出していた。
  円錐グラデーション（`createConicGradient`）で一筆描きに変え、非対応環境では平均的な明るさの輪に落とす。
- 泡の鏡面反射を、変換をかける**前**の座標でグラデーションを作っていたため位置が二重にずれ、
  意図した左上ではなく右下に散っていた。変換後の座標で作るよう直した。
- 泡の原板を 224px で焼いていたが、画面に出るのは最大でも直径60px程度。
  縮小の費用だけが乗っていたので表示サイズに見合う解像度に落とした。
- 光レイヤを上部76%までしか合成しないのに、減光の勾配が画面下端で0になる設定のままだったため、
  境目に薄い段差が出る状態だった。76%で丁度0になるよう勾配を直した。
- 「速さが勝率に効くか」を最初に測ったとき効果ゼロと出たが、原因は検証側だった。
  比較に使った打ち手が理論上の優劣を読んで大半の回戦をベット段階で降りてしまい、
  **役作りがほとんど発生していなかった**（溺死0%・呼吸1枚が手がかり）。
  毎回戦かならず役作りまで進む条件に直したところ、速い側の勝率63.5%が出た。
